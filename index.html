IPONZ SaaS Migration — Sample SQL Reconciliation & Mismatch Investigation

// RECREATED SOURCE-TO-TARGET RECONCILIATION QUERY (SYNTHETIC SCHEMA)
SELECT
  s.ip_case_id,
  s.legacy_status_code,
  t.saas_lifecycle_state,
  s.priority_filing_dt AS src_filing_dt,
  t.priority_filing_dt AS tgt_filing_dt,
  CASE
    WHEN t.ip_case_id IS NULL THEN 'MISSING_IN_TARGET'
    WHEN s.expected_target_state <> t.saas_lifecycle_state THEN 'STATE_RULE_MISMATCH'
    WHEN DATEDIFF(day, s.priority_filing_dt, t.priority_filing_dt) <> 0 THEN 'DATE_OFFSET_DRIFT'
    ELSE 'RECONCILED_OK'
  END AS recon_verdict
FROM staging_legacy_ip_cases s
LEFT JOIN target_saas_ip_registry t
  ON s.ip_case_id = t.external_legacy_ref
WHERE s.migration_wave = 'WAVE_03_TRADEMARKS';
MISMATCH DETECTED IN TRIAL LOAD (142 OF 50,000 SYNTHETIC RECORDS)

Symptom: 142 historical trademark records returned DATE_OFFSET_DRIFT (-1 day) and STATE_RULE_MISMATCH when transitioning from RENEWAL_GRACE.

How I Investigated & Resolved It: Joined the MuleSoft transformation payload logs against the legacy SQL timestamps and proved that timestamps filed during NZ Daylight Saving Time (NZDT) were being cast to UTC without timezone offset preservation before truncation to DATE. Updated the ETL mapping rule with the data engineering lead and re-ran Wave 03 reconciliation to achieve 100.0% parity (50,000 / 50,000 records) prior to dress rehearsal sign-off.

AC COVERAGE: 83 / 84 (98.8%) RECOMMENDATION: NO-GO (HOLD RELEASE)

Active Defect (Sev-1 / P1): Under 4G packet loss, tapping “Pay Now” twice within 1.8s triggers a race condition between the Windcave webhook callback and the client polling loop—resulting in a confirmed bank debit while the application status remains PENDING_PAYMENT.

MY RELEASE REASONING & STAKEHOLDER RECOMMENDATION

Even though 98.8% of functional tests pass, any defect that takes a customer's payment without issuing their visa/application receipt—or risks a double charge—is an immediate Release Blocker (No-Go). I recommend holding cutover for 24 hours while engineering enforces an idempotency key on the payment session ID and implements a webhook-first state lock.
